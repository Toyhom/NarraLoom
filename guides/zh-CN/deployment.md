# 部署、备份与恢复

[English](../deployment.md) · [简体中文](deployment.md) · [日本語](../ja/deployment.md)

为每个数据目录运行一个后端写入进程。使用专用项目环境，并将运行时数据保存在可写工作区中。模型服务可以运行在其他机器上；配置后端可访问的 URL。

```bash
narraloom serve --workspace /path/to/my-game   --models-config /path/to/models.local.json   --web-dist /path/to/NarraLoom/web/dist   --host 127.0.0.1 --port 18090
```

仅使用 API 时可省略 `--web-dist`。路径相对于 `--workspace` 解析；支持显式绝对路径。`--data-root`、`--output-root` 和 `--secrets-root` 允许主机选择单独的存储位置。默认运行时目录为 `data`、`outputs` 和 `secrets`。

## 访问与身份

内置会话 cookie 用于标识浏览器的库和战役。返回同一服务器时请保留该 cookie。在清除浏览器数据之前，请导出战役备份。Python SDK 将会话保存在私有文件中。恢复已保存的请求时，请使用相同的主机名和端口。

当前部署模型为个人或可信组服务器。对于远程访问，请使用 SSH 隧道或位于同一源下的经过身份验证的 HTTPS 反向代理。将提供商密钥保存在私有环境变量、服务密钥存储或 `secrets_root` 内的文件中。

## 备份

使用战役备份/下载和恢复 UI 或 API 在会话之间迁移冒险。备份包含其完整的创建者状态，包括密钥。原生世界包共享可复用内容；玩家笔记仅导出可见的游戏过程。

对于全实例快照，请优雅地停止其写入进程，并一起复制工作区的数据和引用的资产目录。将模型配置/密钥单独保存。首先恢复到隔离的工作区中，使用兼容的框架版本，并在切换流量之前检查 `/healthz` 和代表性战役。

## 恢复

在浏览器/网络中断后，刷新或轮询现有作业。本地超时不会停止服务器上的工作。重用原始请求 ID；显式重试会继续符合条件的失败/中断工作。重新启动的未完成作业会暴露中断状态。`recovery_required` 错误需要存储恢复和回执检查。

避免在后端进程之间共享活动数据目录。日志锁强制只允许一个写入者。`GET /healthz` 检查应用程序/存储就绪状态；模型连接检查是单独的。日志和模型跟踪位于配置的输出目录下。

| 症状 | 检查 |
| --- | --- |
| 模型不可用或 401 | 后端可见的端点、确切的模型 ID 和密钥变量/文件 |
| 无效的结构化响应 | 提供商 JSON 模式、模型能力、输出限制和任务报告 |
| 故事测试失败 | 报告的源文本、引用和路由；编辑或请求修订，然后重新测试 |
| 现有写入者错误 | 另一个进程拥有同一数据目录 |
| 会话找不到旧内容 | 浏览器 cookie、主机名/端口，或从导出的备份恢复 |
| 前端不可用 | 通过 `--web-dist` 传递的构建路径；`npm run build` 已完成 |
| 可选 Avatar 创建不可用 | 配置执行器及其模型依赖项；可导入便携式成品资产 |

有关安装检查，请参阅[测试](../reference/testing.md)；有关可选展示，请参阅 [Avatar 设置](../reference/avatars.md)。
