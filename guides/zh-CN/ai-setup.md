# 使用 Codex 或 Claude Code 进行设置

[English](../ai-setup.md) · [简体中文](ai-setup.md) · [日本語](../ja/ai-setup.md)

在你的编码助手中打开该仓库，并调整此任务的前四行：

```text
设置 NarraLoom 并验证一个可运行的故事游戏框架。
我偏好的界面/内容语言：[英语 / 简体中文 / 日语 / 另一种内容语言]
我的模型选择：[提供商 API / 现有本地服务 / 为我的硬件推荐]
我的环境和工作区目录：[选择路径或推荐新路径]
我的目标：[参考前端 / 后端 API / 模型对比]

阅读 README.md、guides/quickstart.md、guides/models.md、guides/developers.md
以及适用的工作区说明。检查 Python、Node、存储以及任何
现有的推理服务。在共享硬件上，使用其既定的账户
和 GPU 调度工作流。

1. 选择一个专用环境并安装后端。在需要时构建参考
   前端。将缓存和运行时文件保留在工作区中。
2. 配置提供商端点、确切的模型 ID、JSON 模式和私钥
   来源。复用兼容的现有服务。说明模型角色映射。
3. 启动一个后端写入器。检查 /healthz、/docs 和所选模型模块。
4. 运行 python scripts/verify.py --distribution。为
   破坏性或重启检查使用单独的工作区。
5. 使用配置好的真实模型，创建一个小型世界和故事，检查其
   自动测试报告，启动一个战役，提交一个动作并在刷新后
   恢复它。当目标是后端使用时，演练 SDK 持久化。
6. 报告 URL、配置位置、验证结果以及确切的
   启动/停止说明。将凭据和生成的私有内容排除在
   提交和公开报告之外。

如果我带来一个研究模型，请使用 guides/research.md 更改一个模块，并
记录其实际响应模型、失败、延迟和用量。
```

可选的 2D 创作有其自己的执行器和模型依赖。在选择时进行配置；参见 [Avatar](../../docs/AVATARS.md)。
